B

Baseline + PICARD

  1. InputPertanyaan + skema
  2. EncoderT5-small yang sama
  3. DecoderLogits → kandidat top-2
  4. PICARD guardParser + skema menerima atau memask token
  5. LoopBeam melanjutkan token valid
  6. OutputSQL → SQLite

Mode aktif: parse_with_guards, schedule incremental. Token yang ditolak diberi skor −∞ sebelum beam berikutnya.

Cara membaca hasil

SQL berbeda menunjukkan dampak akhir decoding. Trace rejected menunjukkan intervensi langsung PICARD. SQL yang sama tidak otomatis berarti PICARD tidak aktif—parser bisa menerima kandidat yang sama pada seluruh langkah.
